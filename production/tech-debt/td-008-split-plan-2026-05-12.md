## Recommandations par fichier

### DONE — split déjà effectué au maximum actionnable

- **`audio_system.gd`** (544 l.) : proxy properties (lignes 85–198) sont une couche de
  compatibilité tests obligatoire. Toute extraction supplémentaire crée plus de boilerplate
  qu'elle n'en économise. Max atteint.

- **`level_system.gd`** (301 l.) : 1 ligne au-dessus du seuil. 4 handlers extraits.
  Proxy API obligatoire pour compatibilité tests (TD-009 encapsulation breach déjà documenté).
  Actionnable réel = 0. À considérer DONE.

- **`combat_system.gd`** (299 l.) : sous le seuil. DONE.

- **`vfx_system.gd`** (306 l.) : 6 lignes au-dessus. Proxy layer = résidu architectural
  non-extractible sans rompre l'API tests. DONE.

### DEFER — hot-path ou contrainte ADR bloquante

- **`movement_controller.gd`** (652 l.) : le corps de `_physics_process` (~120 l.) et les
  helpers appelés depuis lui (`_try_start_dash`, `_update_wall_run`, `_apply_dash_state`,
  etc.) ne peuvent pas être délégués à un RefCounted sans passer un pointeur `self` à chaque
  tick — ce qui introduit un appel indirect sur le chemin 60 Hz et casse ADR-0005 D-4
  (emit depuis `_physics_process` uniquement). Déjà documenté en commentaire tête de fichier.
  Seuil raisonnable pour un CharacterBody3D avec 5 états. **DEFER P3**.

- **`input_manager.gd`** (439 l.) : le commentaire lignes 13-15 documente explicitement
  pourquoi 300 l. n'est pas atteignable (hot-paths `_unhandled_input` ~1000 Hz +
  `_physics_process` + API publique zero-alloc). ADR-0004 D-8 interdit les appels indirects
  sur ces chemins. **DEFER P3**.

### SPLIT recommandé — gains rapides, risque faible

#### 1. `shop_controller.gd` (401 l.) — SPLIT RECOMMANDÉ
**Helper proposé** : `src/ui/shop/shop_animations.gd` (RefCounted stateless).

Bloc extractible : méthodes `_animate_credit_counter`, `_animate_purchase_pulse`,
`_animate_disabled_shake`, `_find_credit_value_label`, `_find_upgrade_card` +
constantes animation `_COUNTER_TWEEN_DURATION_S`, `_PULSE_DURATION_S`, `_PULSE_SCALE`,
`_SHAKE_DURATION_S`, `_SHAKE_AMPLITUDE_PX`, `_SHAKE_COOLDOWN_MS` (lignes 287–402 soit ~116 l.).

Le bloc animation est cohésif, sans état partagé avec le cycle purchase, et ne dépend
que de `_reduce_motion` + `_animation_log` + `_shake_cooldown_until_ms` (3 champs
injectables). Résidu ShopController ~285 l. — sous le seuil.

**Effort** : S (2–3 h). **Risque** : Faible — pas de test injection sur ce bloc.

#### 2. `credit_economy.gd` (349 l.) — SPLIT POSSIBLE
**Helper proposé** : `src/core/credit_signal_handlers.gd` (RefCounted).

Bloc extractible : `_on_level_active`, `_on_enemy_killed`, `_on_secret_collected`,
`_on_state_changed`, `_on_request_new_run`, `_hydrate_from_save`, `_persist_to_save`
(lignes 172–349 soit ~178 l.). Ces handlers ne mutent l'état que via une référence
injectée vers l'autoload parent (pattern miroir `audio_combat_handler.gd`).

Résidu CreditEconomy ~171 l. — bien sous le seuil.

**Effort** : S (3–4 h). **Risque** : Moyen — tests unitaires accèdent directement aux
handlers (ex. `_on_enemy_killed` appelé dans les tests) — nécessite des proxy methods
sur l'autoload (pattern établi dans audio_system.gd). Vérifier la couverture de tests
avant de procéder.

#### 3. `camera_system.gd` (410 l.) — SPLIT POSSIBLE (moindre priorité)
**Helper proposé** : `src/gameplay/camera/camera_perf_metrics.gd` (RefCounted).

Bloc extractible : `_compute_percentiles`, `get_process_cost_percentiles`,
`get_mouse_latency_percentiles`, ring buffers `_process_cost_samples`,
`_latency_samples`, `_process_cost_write_idx`, `_latency_write_idx` (~50-60 l.).

**Contrainte** : les tests GdUnit4 accèdent directement aux membres ring-buffer
via injection (pattern story-012). Un split nécessite des proxy properties sur
`CameraSystem` (pattern audio_system.gd). Effort M. Gain ~50 l. → 360 l. résidu.
**Risque** : Moyen. Gain modeste vs effort.

## Notes architecture

- Le pattern proxy-properties (audio_system.gd → audio_combat_handler.gd) est la
  technique validée pour préserver la compatibilité des tests lors de splits sur autoloads.
- Les `DEFER` ne sont pas des dettes mais des décisions architecturales conscientes :
  les commentaires en-tête des fichiers le documentent.
- `level_system.gd` (301 l.) et `vfx_system.gd` (306 l.) sont nominalement au-dessus
  du seuil mais le résidu proxy non-extractible est ~6-7 lignes — pas actionnable.
  Recommandation : considérer le seuil à 310 l. pour ces cas de proxy obligatoire.
