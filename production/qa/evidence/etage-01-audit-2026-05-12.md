## 1. Statut BLOQUANTS Cluster B initiaux

### B1 — CollisionShape3D sans `shape` assignée sur 4 primitives
**RESOLVED.**
Toutes les primitives instanciées (Mezzanine × 6, ShaftConnector × 2, Atrium × 1, VerticalShaftRoom × 1) sont référencées via `instance=ExtResource(...)` — leurs shapes sont définies dans leurs propres `.tscn`. Aucune `CollisionShape3D` inline sans `shape =` n'est présente dans `etage_01.tscn`. Les shapes définies inline (Room_01, Room_03, Room_09, gauntlet, pylons, covers, parkour platforms, debug floor, etc.) ont toutes un `shape = SubResource(...)` explicite.

**Exception à noter** : `StaticEnvironment/Room_01/Ceiling_01` contient `CeilingMesh` (MeshInstance3D sans mesh assigné — `mesh` absent) et `StaticEnvironment/Room_09` a plusieurs `WallLeftMesh`, `WallRightMesh`, `WallBackMesh`, `CeilingMesh` sans `mesh =`. Ces nodes sont des MeshInstance3D sans mesh, **pas** des CollisionShape3D sans shape — invisible en jeu, aucune incidence sur la physique, pas de violation lint.

### B2 — Room_05 COMBAT : murs wall-run absents (AC-LVL-15)
**STILL OPEN — partiellement.**
Room_05 (COMBAT, Z=38) ne contient que des Mezzanines (`Mezzanine_03`, `Mezzanine_03b`, `Mezzanine_03c`) toutes `visible = false`. Aucun `StaticBody3D` portant `metadata/wall_run_enabled = true` n'est présent dans Room_05.

Le lint `validate_wall_run_surfaces` cherche uniquement les `StaticBody3D` avec meta `wall_run_enabled=true` sous `StaticEnvironment`. Room_05 n'en a pas. **Ce n'est pas une violation du lint AC-LVL-15** (le lint est opt-in via méta) mais l'intention de design d'avoir des murs wall-run dans la salle COMBAT_05 reste non implémentée. Si le design requiert wall-run dans Room_05, il faut ajouter des `StaticBody3D` avec `wall_run_enabled=true`. Le lint CI passe sur ce point.

Les murs wall-run présents sont dans **Room_03** (COMBAT, Z=14) : `WallRunWall_01` et `WallRunWall_02`, taille `0.3×4.5×4.0` m — height 4.5 ≥ 4.0 ✓, length max(0.3, 4.0)=4.0 ≥ 3.0 ✓, méta `wall_run_enabled=true`. Ces deux surfaces passent AC-LVL-15.

**Le gauntlet** (`GauntletLeft`, `GauntletRight`) n'est **PAS** sous `StaticEnvironment` (voir B3 ci-dessous) — le lint `validate_wall_run_surfaces` ne les parcourt pas (il scanne uniquement sous `StaticEnvironment`). Les murs gauntlet ont `shape_gauntlet_wall` de taille `0.3×5.0×30.0` — height 5.0 ≥ 4.0 ✓, length 30.0 ≥ 3.0 ✓, mais ils sont **hors scope du lint AC-LVL-15**.

### B3 — Nodes top-level hors hiérarchie canonique
**STILL OPEN — BLOQUANT CI.**

Les nodes suivants sont enfants directs de la racine `Etage01` mais hors des 4 sous-arbres canoniques (StaticEnvironment / InteractiveVolumes / SpawnMarkers / EtageExitTrigger + OnboardingAnchors étage-1-only) :

| `DirectionalLight3D` | DirectionalLight3D | HORS-CANON |
| `GauntletWalls` | Node3D (+ StaticBody3D enfants) | HORS-CANON |
| `GauntletPylons` | Node3D (+ StaticBody3D enfants) | HORS-CANON |
| `BossStairs` | Node3D (+ StaticBody3D enfants) | HORS-CANON |

| `SpireTowerBase` | MeshInstance3D | HORS-CANON |
| `SpireTowerTip` | MeshInstance3D | HORS-CANON |
| `SpireLED` | MeshInstance3D | HORS-CANON |
| `AmbientDust` | CPUParticles3D | HORS-CANON |

Le lint `validate_scene_hierarchy` utilise `find_child(required, false, false)` (non récursif) — il vérifie la **présence** de StaticEnvironment / InteractiveVolumes / SpawnMarkers / EtageExitTrigger comme enfants directs, **sans rejeter les nodes supplémentaires**. La hiérarchie canonique d'ADR-0011 interdit formellement les sous-arbres top-level hors des 4 mandatoires, mais **le lint v.actuel ne le vérifie pas par assertion négative**. Par conséquent : **pas de violation lint CI** sur ce point.

**Impact design** : Les `GauntletWalls`, `CoverColumns`, etc. contiennent des `StaticBody3D` avec `collision_layer=8` (LAYER_ENVIRONMENT) et `collision_mask=0` — la physique fonctionne. Mais leur position hors `StaticEnvironment` les exclut des checks `validate_collision_layers`, `validate_wall_run_surfaces`, `validate_room_archetype_invariants`. **Les budgets DC/SB3D par room sont sous-estimés.**

**Player top-level** : La présence du `Player` comme enfant direct de la scène est un pattern proto-playtest. Le lint ne le flagge pas mais c'est une dette de design intentionnelle (playtest only).

## 2. Violations nouvelles détectées (commits visuels post-session)

### V-01 — StaticBody3D hors StaticEnvironment échappent au lint collision layers
**ADVISORY (non bloquant CI).**
`GauntletLeft`, `GauntletRight`, pylons, cover columns, parkour platforms, debug floor, boss stairs ont `collision_layer=8` et `collision_mask=0` — conformes ADR-0008. Mais `validate_collision_layers` ne les parcourt pas (scan limité à `StaticEnvironment`). Aucune violation lint, mais conformité non vérifiée par CI.

### V-02 — MeshInstance3D top-level (SpireTowerBase, SpireTowerTip, SpireLED, AmbientDust)
**ADVISORY.**
Nodes purement visuels / décoratifs, pas de collision. Aucun impact physique. Non comptabilisés dans les budgets DC per-room (favorable aux budgets) mais hors hiérarchie canonique.

### V-03 — DC agrégat potentiellement sous-estimé
**À VÉRIFIER.**
Le lint compte les `MeshInstance3D` via `find_children` **only** sous les rooms dans `StaticEnvironment`. Les nombreux `MeshInstance3D` dans `GauntletWalls`, `GauntletPylons`, `CoverColumns`, `ParkourPlatforms`, `BossStairs`, `SpireTower*` (LED strips, meshes) ne sont **pas comptabilisés** dans le DC agrégat. Le budget F2 ≤ 350 DC sera sous-estimé côté lint — le count réel en runtime sera plus élevé. Cela est cohérent avec le score actuel "6 violations" mentionné en active.md (pas de violation DC agrégat détectée) mais le risque de dépasser les 350 DC réels est présent.

### V-04 — SecretCollectVolume_02 Y=36 — question résolue
Y=36 est confirmé intentionnel : correspond au `SecretAnchor_02` à Y=36.2 (distance 0.2 m — bien ≤ 10 m). La position haute (sommet Atrium Room_07 soulevé à Y=8+room y) est cohérente avec `required_ability = dash`. Pas de violation.

### V-05 — Collision layers des Area3D EtageExitTrigger
`EtageExitTrigger` est top-level (enfant direct de racine), avec `collision_layer=16` et `collision_mask=1` — conforme ADR-0008. Le lint `validate_collision_layers` scanne uniquement `InteractiveVolumes` pour les Area3D, donc EtageExitTrigger n'est pas couvert, mais ses valeurs sont correctes.

### V-06 — CPUParticles3D AmbientDust : emitting=false
`AmbientDust` a `emitting = false`. Aucune particule ne s'affiche au lancement. Probablement activé via `etage_01_init.gd` en runtime — à vérifier lors du playtest. Pas de violation lint.
